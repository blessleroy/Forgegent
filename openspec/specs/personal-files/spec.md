# personal-files Specification

## Purpose
员工个人文件空间：独立持久的文件列表与任务关联、服务端 ACL 保护的本机存储、路径安全防护、配额限制、任务输入引用与成果写回、备份一致性。

## Requirements

### Requirement: 独立持久文件空间

每名员工 SHALL 拥有独立、持久化的文件空间，含个人上传文件、任务成果、版本与任务关联；V1 使用本机目录 + SQLite 元数据，不使用对象存储。

#### Scenario: 成果落入个人空间
- **WHEN** 一个任务产出文件
- **THEN** 文件经服务端校验转存到员工个人空间并出现在其文件列表

### Requirement: 服务端 ACL 与受保护下载

文件下载 MUST 经服务端受保护接口且属主校验；下载路径解析 MUST 复用存储层的全部防御（storageKey 严格格式校验、realpath/符号链接包含检查、流式读取），防御纵深 MUST 与存储层一致——MUST NOT 以裸路径拼接绕过存储层直接读盘。

#### Scenario: 他人文件 ID 不可访问（AT-08）

- **WHEN** 员工 A 以猜测/伪造的文件 ID 或 URL 尝试下载员工 B 的文件
- **THEN** 请求被拒绝；构造 `../` 路径或符号链接同样无法逃逸存储根

#### Scenario: 下载防御与存储层一致

- **WHEN** 数据库中的 storage_key 被篡改为非常规值（含路径分隔符等）
- **THEN** 下载接口经存储层校验拒绝该值，而非拼出可逃逸路径

### Requirement: 路径与挂载安全

系统 MUST 防止路径穿越、符号链接逃逸、任意绝对路径访问与通过可猜测 ID 获取他人文件；任务沙盒 MUST 只获得本次已授权文件的副本或受控挂载，MUST NOT 挂载整个用户目录。

#### Scenario: 路径穿越被阻断
- **WHEN** 请求中构造 `../` 路径或符号链接指向他人目录
- **THEN** 访问被拒绝且留痕

### Requirement: 配额与类型限制

文件上传 MUST 施加单文件大小上限、单用户总量配额（默认 50MB/2GB）与类型白名单（默认覆盖常见文档/图片/压缩等非可执行类型，可执行与脚本类默认拒绝；白名单与配额上限为服务端配置、Admin 可调生效）；V1 保留策略默认为不自动删除、仅配额限制（N10）。

#### Scenario: 超配额上传被拒

- **WHEN** 员工上传使个人空间超过配额上限
- **THEN** 上传被拒绝并提示当前用量与上限

#### Scenario: 类型白名单生效

- **WHEN** 员工上传默认白名单之外的文件（如可执行文件）
- **THEN** 上传被拒绝并说明允许的类型范围；Admin 调整白名单后按新配置生效

### Requirement: 任务输入引用与删除保护

`files` 记录中任务字段仅表示产出该文件的任务；任务输入引用 SHALL 通过独立关联关系表达；被运行中任务引用的文件被删除时 MUST 阻止并提示（软删除语义）。

#### Scenario: 引用中文件不可删
- **WHEN** 员工删除一个正被运行中任务引用的上传文件
- **THEN** 系统阻止删除并说明该文件仍在使用

### Requirement: 多用户文件隔离

A、B 同时使用同一 Agent 时，其会话、临时文件与成果 MUST 相互隔离（AT-07）。

#### Scenario: 并发任务文件互不可见
- **WHEN** A 与 B 同时运行同一 Agent 的任务
- **THEN** 各自沙盒仅含各自授权文件副本，成果分别写回各自空间

### Requirement: 备份一致性

系统 MUST 提供数据库与文件系统的备份/恢复说明，要求备份时能获得一致性数据快照。

#### Scenario: 备份恢复可验证（AT-19）
- **WHEN** 按说明备份后恢复到测试环境
- **THEN** 账号、发布版本、文件元数据与文件内容一致
